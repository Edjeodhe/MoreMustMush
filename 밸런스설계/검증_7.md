## 3. 난수·결정성·무한 루프·비용

- **결정적이다.** UnityEngine.Random 전역 하나만 쓰고 순서가 정해져 있다. 같은 시드면 같은 결과가 나온다. 다만 지금과 순서가 다르다(종 먼저 MaxCol개 → 위치 → CreateColony). 그래서 **옛 시뮬 기록과 시드별로 비교할 수 없다.** 기준선을 다시 잡아야 한다.
- **난수 소비량** (군락 하나·계획 한 번 기준)
  - 무작위 시도 한 번: Random.value 3+2n번(rot 1, 둘레 n개 × 2, 위치 2)이다. 30번 다 실패하면 (3+2n)×30번이다.
  - 격자 보충: 빈 점 고르기 RandI 1번이다. 둘레 오프셋은 이론안에 명시가 없다. **오프셋은 격자 위치를 고른 뒤 rot·n개를 한 번 더 뽑는다(1+2n)**로 정해야 한다.
  - 다시 놓기: 종·둘레 수는 다시 뽑지 않고 위치만 다시 뽑는다.
- **무한 루프 없음.** 줄이기는 ×0.93씩 S_ABS 0.45에서 멈춘다. 최대 ⌈ln 0.45/ln 0.93⌉+1 ≈ 13번이고, 재계산에서 본 최대는 8번이다. s_min 한 번 들르기는 `s > sm`일 때만이라 같은 값에서 반복하지 않는다. 재생은 지금처럼 0.5초 재시도다.
- **비용** (격자 한 번)
  - 격자 점 수: L0 1.9천~4.2천, md_map2 1.45만~1.95만이다.
  - 점마다 AreaFree를 부른다(군락 ≤ 25 + 장치 5 + 발사점). md_map2에서 한 번에 Overlap 약 50만 번이다.
  - 판 시작 최악은 다시 놓기 8회 × 격자 여러 번으로 수천만 번 → WebGL에서 한 프레임 수십 ms 끊김이 날 수 있다.
  - 재생 실패 때도 0.5초마다 격자를 돈다.
  - **test에서 판 시작 ms와 재생 격자 호출 수를 잴 것.** 크면 재생 쪽만 16px 격자를 쓰거나, 계획 중 격자 결과를 재사용한다.

## 5. s0와 등급 섞임 (E4)

- 공식은 R_REF 32(일반 등급)로 잡아서 섞임과 무관하게 같은 s를 낸다.
- `s_mix_out.txt` (장치 3): 후반 섞임이면 **s 1.00으로도 14개가 다 놓인다.** 17개도 0.98이다. 공식은 0.80·0.72로 줄인다. 일반 등급만이면 0.81로 같다.
- 후반 버섯 80% 크기는 근거 없는 축소다. 맞히기 손실(약 ×0.92)과 화면 크기 손해가 생긴다.
- **수정안:** 계획한 종으로 s0를 푼다.

  ```
  Σ_i π·(3.9·r_i·s + 17)² = COL_PACK · A_free
  → a = Σ(3.9 r_i)², b = 34·Σ(3.9 r_i), c = 289·N − COL_PACK·A_free/π
  → s0 = clamp((−b + √(b² − 4ac)) / 2a, COL_S_ABS, 1)
  ```

  일반 등급만이면 지금 공식과 같다. 줄이기 단계가 뒤를 받친다.
- **재생 주의 (refill).** 섞인 등급으로 다 놓은 뒤 작은 군락 자리에 일반 등급이 재생되면 실패가 잦다. 30번 실패는 25~70%다. 격자까지 실패는 md_map2 0%, z1.2 12%, L0 20%다. 0.5초 뒤 다른 종으로 다시 하므로 막히지는 않는다. 동역학에 포함돼 있다.

## 6. 노드 문구 (a-6)

- `ed_cols` "최대 {0}개"를 지금 필드 기준으로 바꾸는 데 **찬성한다.** 지금 문구는 md_map2 맑음 기준 숫자라, L0에서 27을 보여 주고 실제로는 2.5개다.
- **하지만 그대로 쓰면 +0 구매가 드러난다.**

  | 필드 | ed_cols 0~4 → II1 → II2 |
  |---|---|
  | L0 | 2·3·**3**·4·5 → 6 → **6** |
  | L1 | … → 7 → **7** |
  | L3 | … → 10 → **10** |
  | L4 | 3·5·7·9·**9** → … |

  이론 표와 같다. 이 칸에서 사면 군락이 늘지 않는다. 문구가 정직해지면 사용자가 "+0"을 보게 되므로, 사용자에게 알리고 허용할지 정해야 한다.
