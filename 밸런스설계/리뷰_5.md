# 5회차 코드 리뷰 (읽기 전용 · 정적 검토, Unity 컴파일 미실행)

범위: 코드_5.md + 지정된 파일의 git diff. 판 번호 혼용은 Assets/Scripts·Assets/Editor 전체 grep으로 확인.

## 결론
CRITICAL 0 · HIGH 0 · MEDIUM 4 · LOW 5. 컴파일 오류로 보이는 곳은 찾지 못했다. 병합을 막을 문제는 없다.

## ① 컴파일 (정적 확인)
- `COST_MUL` float→double const: 사용처(Defs.Nodes.cs:261, Game.cs:117·121, SaveMigration.cs:45·178, BalanceSim.Ckpt.cs:49, SinkChecks.cs:37)가 모두 double 식이라 문제없다. 0.9×정수가 올림에서 튀지 않는지도 확인했다(정수×0.9의 곱은 정확히 정수로 반올림된다).
- `ContentStage`·`StageLabel`·`RoundOfStage`·`TUT_ROUNDS`: Game/RoundSim/SettleScreen/StageSettle/MainGameController/BalanceSim 모두 `using static MoreMush.Defs`가 있다. BossTune은 `Defs.`로 한정해 쓴다. StageHUD는 `Defs.StageLabel`로 한정한다.
- `RoundSim.Balls.cs`: `BossCleared`·`NextBossStage`는 `using static Game/Defs`로 풀린다. RoundSim에 같은 이름의 멤버는 없다(`bossCleared`는 소문자 지역·필드). `Mathf`·`UnityEngine` using이 있다. `sporeSlowMul`은 인스턴스 필드이고 `RoundSim.Start`(static)에서 `r.sporeSlowMul`로 같은 클래스 안에서 쓰므로 접근 제한 문제가 없다.
- `E["md_map2"]` 람다: 지역 함수 `F(double,int)`·`Loc.F`가 따로 있어 충돌하지 않는다. `z`는 이 파일의 다른 곳에서 쓰이지 않는다(CS0136 없음). `W / z`는 const int / float = float이고 `JsRound`는 md_map 줄과 같은 형태다. `MapZoom2()`는 `V`(private static)와 같은 partial 클래스 `Defs` 안에 있어 접근할 수 있다.
- `Defs.Boss.cs`의 `BossGem` 식 본문 줄바꿈, `EarlyHpMul`의 double 계산, `Mathf.Min(float, float)`: 문제없다.

## ③ SaveMigration.ToV9 (SaveMigration.cs:136~141)
- 두 번 적용: `Run`이 `g.v < 9`일 때만 호출하고 끝에서 `g.v = Math.Max(g.v, CURRENT)`로 올려 두 번 적용되지 않는다. 로드 직후 저장 전에 크래시하면 v8로 남아 다시 +4가 되지만, 이는 다른 마이그레이션도 같은 구조다.
- 새 세이브: `SaveData.v`의 초기값이 `CURRENT`(9)라 마이그레이션을 건너뛴다. 정상.
- `stage <= 1 && tut < 3` → 건너뜀(첫 판 전). `stage == 1 && tut >= 3`(옛 세이브에서 `tut`을 3으로 만든 경우)은 5가 된다. `stage > 1 && tut < 3`(튜토리얼 도중)도 +4가 되어 T2~T4를 건너뛴다. 모두 의도와 맞다.
- 순서: ToV8의 `g.stage >= 7`은 옛 번호로 평가된 뒤 ToV9가 돈다. 맞다.
- **LOW** 옛 세이브의 온보딩이 앞당겨진다. 옛 2~3스테이지 세이브가 내부 6~7이 되어 날씨(`> 5`)와 도감(`> 3`)이 즉시 열리고, `EarlyStage`(6 이하) 종 제한도 풀린다. 보스·지역·체력 위치는 유지된다. 알림이 한꺼번에 뜨는 것만 확인한다.
- **LOW** 옛 환불(SaveMigration.cs:45·178)이 이제 ×0.9로 환불된다(manager가 이미 기록). 해당 마이그레이션(v3·v6~7)은 오래된 세이브에만 돈다.

## ④ ResetPresetOnPlay (Defs.cs:105~108)
- `#if UNITY_EDITOR` 안이라 빌드에는 들어가지 않는다.
- 호출하는 쪽을 확인했다(BalanceBatch.cs:86, BalanceJob.cs:44, OptimizationChecks.cs:37·41). 모두 `ApplyPreset(id, false)`라 PlayerPrefs에 쓰지 않으므로, 플레이 시작 때 저장 프리셋으로 되돌아가는 방식이 실제로 버그를 고친다.
- **MEDIUM** (확인 필요) `SubsystemRegistration`에서 `LoadPreset()`을 부르면 `Defs`의 정적 초기화(Db 로드·노드 조립)가 그 시점에 일찍 돈다. 에디터에서는 Db가 파일을 읽으므로 Resources 문제는 없지만, `db.json`이 없거나 DB가 깨졌으면 플레이 시작마다 `TypeInitializationException`이 난다(원래는 더 늦게 같은 예외가 난다). 한 번 에디터 플레이로 확인하고, 걱정되면 `BeforeSceneLoad`로 옮기는 것도 방법이다(App.Boot도 BeforeSceneLoad).
- **LOW** 도메인 리로드를 끈 경우 TUNE 외에 밸런스 도구가 바꾸는 정적 값(`ZONE_RAMP`, `SIM_HP1`, `BOSS_LOOP_HP_MUL`, `BOSS[id].hpMul`, GATE 값)은 되돌리지 않는다. 같은 증상이 다른 값에서 나오면 여기에 같이 넣는다.

## ⑤ 포자 BossesCleared 루프 (RoundSim.Balls.cs:82~87)
- 무한 루프 아님. `NextBossStage(s+1) >= s+1 > s`라 `s`가 매번 `BOSS_EVERY`(DB 최솟값 1) 이상씩 늘고, `BossCleared(s) = ContentNow() > s`는 유한한 값에서 거짓이 된다.
- `G == null`이면 `ContentNow() = 1`이라 첫 보스(10)에서 바로 끝난다.
- 판 시작 때 한 번만 도는 O(콘텐츠/10)이라 비용도 문제없다.
- **LOW** 주석이 낡았다. Balls.cs:432 "상한 -45%"와 Balls.cs:79 "(0.75 → 0.65)"는 현재 값(`SPORE_SLOW_MAX = 0.35`, 기본 0.75)과 다르다. 코드_5.md는 0.35 적용이라고 적었으니 주석만 고친다.
- **LOW** `SPORE_SLOW_*`와 `EARLY_HP_NERF*`가 코드 상수다(Defs.Boss.cs 머리말은 밸런스 상수를 DB Const에서 읽는다고 적음). 프로젝트 방침이 "Const는 꼭 필요할 때만"이라 위반은 아니다. 가안 확정 뒤 옮길지만 정한다.

## ⑥ md_map2 노드가 DB에 없을 때
- 예외 없음. `Lv("md_map2")`는 `G.nodes.TryGetValue`라 없으면 0이고, 그러면 `MapZoom2()`(= `V("md_map2",1)` → `NODE["md_map2"]`가 KeyNotFound를 던지는 경로)를 부르지 않고 `MAP_ZOOM[Lv("md_map")]`로 간다.
- `E["md_map2"]`는 람다를 등록만 하고 `NODE[...]`를 읽지 않는다. `E`에 NODE에 없는 키가 있어도 `BuildEffects`/`CheckTree` 경로가 E를 NODE로 역참조하지 않는다.
- 위험 한 가지(**LOW**): DB 반영 전에 세이브에 `md_map2` 레벨이 들어갈 일은 없다. 반대로 DB에는 있고 코드가 없는 경우는 해당 없음(코드가 먼저 들어갔다).
