# 밸런스설계 — 에이전트 공유 공간

재화 밸런스를 네 에이전트가 나눠 맡고, 여기서 현황·결과·요청을 주고받는다. 정의는 `.claude/agents/balance-*.md`.

| 이름 | 역할 | 산출물 |
|---|---|---|
| `manager` | 관리자(메인): 할당·감시·정정·코드 적용 | `현황/manager.md`, `문서.md` |
| `research` | 자료조사 (Sonnet): 레퍼런스(Bills Must Be Paid)·인크리멘탈 레벨 디자인 → 원칙 P1~Pn | `조사.md` |
| `theory` | 이론 수치: 판 수입 근사 + 가격·효과 수치안 | `이론.md`, `BalanceData/theory/` |
| `verify` | 이론 검증: 공식 일치·독립 재계산·조건·민감도 | `검증.md` |
| `test` | (Sonnet) 시뮬(Unity 배치 봇) + 실제(에디터·MCP) | `테스트.md`, `BalanceData/` |

## 흐름

기본 순서는 조사 → 이론 → 검증 → (메인이 코드 적용) → 테스트. 그 위에 **누구든 누구에게나 요청**할 수 있다.

```
            ┌──────────── 근거·사례 조사 요청 ────────────┐
            ▼                                              │
research ◀──▶ theory ◀──▶ verify ◀──▶ test              (모든 쌍 양방향)
   ▲            ▲  └──── 측정 요청(Measure) ────▶ test     │
   └────────────┴──────── 체감 기준·차이 원인 ◀────────────┘
```

예:
- 이론이 "레퍼런스에서 다음 구매까지 대기 시간이 얼마인지" 필요 → `theory#2 → research`
- 이론이 "공격력 III 2레벨 구성에서 판 수입" 측정 필요 → `theory#3 → test`
- 검증이 "이 근사는 시뮬로만 확인됨" → `verify#1 → test`
- 테스트가 "이론보다 15판 빠름, 원인?" → `test#1 → theory`
- 조사가 "원칙 P4가 현재 수치에서 성립?" → `research#1 → theory`

넷 다 동시에 시작할 수 있다. 앞 단계를 기다리지 않고 지금 있는 것(`문서.md`, 기존 시뮬 기록)으로 먼저 하고, 새 결과가 나오면 해당 부분만 다시 본다.

## 모델

- **단순 노동은 Sonnet**(사용자 지시): `research`·`test`는 `model: sonnet`. 관리자가 하던 기계적 일(엑셀 DB 옮겨 적기, 로그 집계, 파일 복사·백업)도 Sonnet 보조 에이전트에 맡긴다
- **추론·이론은 Opus 5.5**(사용자 지시): `theory`·`verify`는 `model: opus`, 관리자(정정·할당·사용자 질문)도 Opus

## 공유 규칙

- **한 파일 = 한 작성자.** `현황/<내이름>.md`와 내 산출물만 쓴다. 남의 파일은 읽기만 한다
- **요청 확인:** 시작할 때 · 단계마다 · 끝내기 직전에 `python 밸런스설계/요청보기.py <내이름>`. 나에게 온 요청을 하던 일보다 먼저 처리한다
- **요청:** 내 파일 "요청"에 `- [ ] #번호 → 대상: 무엇을 · 왜 · 받고 싶은 형태 (시각) [막힘|참고]`
  - `[참고]`는 가정을 두고 계속, `[막힘]`은 다른 일을 먼저 하고 할 게 없으면 반환에 `대기: 내이름#번호`
- **답:** 받은 쪽이 자기 파일 "받은 요청 처리"에 `- [x] 보낸이#번호 → 답 · 결과 경로 (시각)` (못 하면 `거절: 이유 · 대신 누구에게`)
- **답 확인:** 보낸 쪽이 자기 요청을 `- [x]`로 바꾸고 가정했던 부분을 다시 본다
- **`문서.md`와 `Assets/` 코드 적용은 메인 에이전트만** 한다
- 시각은 `HH:MM`, 날짜가 바뀌면 `MM-DD HH:MM`. **반드시 `date +%H:%M`으로 확인해 적는다**(짐작한 시각이 1시간 넘게 틀린 적이 있음)

## 관리자 `manager` (메인 에이전트)

작업을 직접 하지 않고 감시·정정·할당만 한다. 현황은 `현황/manager.md`.

- **할당:** 각 에이전트의 일을 `현황/manager.md` "요청"에 `- [ ] #번호 → 대상: …`으로 적고 그 에이전트를 띄운다(끝난 에이전트는 SendMessage로 이어서)
- **감시:** `현황/`이 바뀔 때마다(감시 스크립트) `요청보기.py`로 전체를 보고, 새 산출물은 직접 읽어 확인한다
  - 사실 확인: 코드 공식·파일 경로·수치가 실제와 맞는지, 출처가 있는지, 조건(×2 · ×4 · 효율 넘김 · R104)을 제대로 쟀는지
  - 틀린 곳은 `manager#번호 → 대상: 정정: 무엇이 왜 틀렸나 · 근거(파일:줄/수치) · 고칠 것`으로 보내고 SendMessage로 알린다
- **테스트 결과 검증:** `test`의 시뮬·실제 결과는 관리자가 원 기록(`BalanceData/balance_job.log`, `balance_phase_s*.json`, Unity 로그)으로 직접 다시 계산해 확인한다. 맞으면 `현황/manager.md` "받은 요청 처리"에 `검증: test#… 확인`, 틀리면 정정 요청
- **배달:** 받는 쪽이 끝났거나 안 떴으면 다시 띄워 요청을 처리하게 한다. `대기: X#n`으로 끝난 에이전트는 답이 달리면 깨운다
- **적용:** `verify`가 통과시킨 수치안만 `Assets/`에 적용하고 `test`에 측정을 할당한다. 반환의 "문서.md 반영사항"을 `문서.md`에 누적한다
- **멈춤:** 같은 요청이 두 에이전트 사이를 3번 넘게 오가거나, 결정이 사용자 몫(목표 시간·레퍼런스 해석·구조 변경)이면 멈추고 사용자에게 묻는다

## 현황 파일 형식

```
# <이름> 현황
지금: (하는 일 한 줄 | 끝: 결과 한 줄)

## 공유할 결과
- 경로 · 요약 · 시각

## 요청
- [ ] #1 → 대상: 내용 · 왜 · 받고 싶은 형태 (시각) [막힘|참고]

## 받은 요청 처리
- [x] 보낸이#번호 → 답 · 결과 경로 (시각)
```
