- 씬을 떠날 때 `timeScale = 1`로 돌려놓는다 (지금은 `OnDisable`, 아래 10 참고).

### 10. 끊김 조사와 최적화 (`9ba9592`·`4504362`)
- 사용자 가설("수확기·버섯을 매번 새로 만들고 파괴한다")은 **아니었다**. 라운드 중 오브젝트는 `Pool<T>`로 재사용되고 Destroy는 없었다.
- 실제 원인 (에디터 측정, 평소 60fps, x4에서 시뮬 약 0.8ms·그리기 약 1.6ms):
  1. **씬마다 풀을 새로 만듦**: 풀이 Stage 씬 밑에 있어 라운드마다 씬과 함께 버려지고, 다음 라운드 시작·첫 발사 때 GameObject 약 1,500개를 다시 Instantiate.
  2. **씬 전환 강제 전체 GC**: `LoadScene(Single)`이 이전 씬을 내리며 `UnloadUnusedAssets`+전체 GC → 이동마다 220~315ms 멈춤.
  3. GC 할당 초당 4~15MB (`new Part`·`Fx`·HashSet 등).
  4. 효과음 클립을 처음 날 때 합성 (타격음 1Hz 단위 120종).
  5. 느린 프레임 뒤 시뮬을 몰아 돌려 더 느려지는 되먹임.
  6. 배치 수 ≈ SetPass 수(130~450): `Art.SetFx`가 매 프레임 MaterialPropertyBlock을 걸어 배칭이 깨짐.
- `9ba9592` (세션 [Stage 라운드 끊김 최적화 구현]):
  - `RoundView`: `App.Leaving` 때 풀을 씬 밖 보관소(`~RoundPoolStash`, DontDestroyOnLoad, 꺼짐)에 맡기고 다음 라운드가 `Adopt`로 다시 씀. 첫 라운드는 프레임 예산 2ms로 미리 채움(`Pool.Grow`). 붓 결 재질 공유.
  - 필드 숫자 칸은 끄지 않고 크기 0으로 숨김, 프리팹 `LocText` 대신 직접 폰트 적용(OnEnable/OnDisable 할당 제거).
  - 시뮬: Part·Fx 재사용, 번개·충격파 HashSet 대여, 지연 실행·종 후보·군락 후보 그릇 재사용. **BalanceSim 지문 동일**.
  - `Art.SetFx`: 효과값이 모두 0이면 속성 블록 제거.
  - `StageController`: 한 프레임 시뮬 8ms 상한(`SIM_BUDGET_MS`). `Snd`: 타격음 10Hz 단위, `WarmRound`로 자주 쓰는 클립 미리 합성.
  - 측정(스테이지 128~129, x4): 2판째 발사 직후 할당 8.8 → 3.7MB/s, 시뮬 할당 수확당 약 절반.
- `4504362` (세션 [씬 전환 GC 끊김 없애기]):
  - `App.Go`: 새 씬을 **Additive**로 올리고, 새 씬 Awake 직후 `SwapFrom`이 이전 씬 루트를 끄고 활성 씬을 바꾼 뒤 `UnloadSceneAsync`. 이전 씬 EventSystem은 미리 끔. 새 씬 Awake가 부모 없이 만든 오브젝트는 새 씬으로 옮김.
  - `Resources.UnloadUnusedAssets`는 **MainMenu로 갈 때만**.
  - 이전 씬이 늦게 내려지므로 정리는 `OnDestroy` → `OnDisable`로: `StageController`(timeScale·I), `LangPopup.ModalHold`(모달 수).
  - 보고된 측정: 씬 진입 멈춤 220~315ms → 37~163ms. 정산·튜토리얼·팝업·메인 메뉴 오가기 정상.
- 남은 개선 후보(안 함): SetPass를 줄이는 아틀라스·재질 정리(위 6), 큰 리소스 정리.

## 작업 요령·주의
- **Unity MCP**: 이번 세션은 `localhost:8080/mcp`를 HTTP로 직접 불렀다(initialize → `mcp-session-id` → `tools/call execute_code`). 지금은 세션 도구(`mcp__unityMCP__*`)로도 잡힌다. Unity를 다시 켜면 MCP 서버도 사용자가 다시 켜야 한다.
- `execute_code`: `Object`는 `UnityEngine.Object`로, 코드 문자열 안 `\n` 금지(Newline in constant).
- **ESC 같은 키 입력 테스트**: 실제 키 보내기(SendKeys)는 포커스를 뺏어 `OnApplicationFocus(false)` 정지가 섞인다. Input System에 가상 키보드(`InputSystem.AddDevice<Keyboard>("TestKB")`)를 붙이고 `QueueStateEvent`로 누른다.
- **테스트 부작용 (매번 되돌림)**:
  - `Application.runInBackground = true`가 ProjectSettings에 남는다 → `PlayerSettings.runInBackground = false`.
  - 플레이 중 폰트 `.mat`의 `_ScaleRatio`가 바뀐다 → `git checkout`.
  - `Assets/Screenshots` 삭제.
- 끊김 측정은 `ProfilerRecorder` 임시 탐침으로 했다(커밋 안 함). 첫 줄 통계가 정적 카운터로 오염되므로 시작 때 초기화.
