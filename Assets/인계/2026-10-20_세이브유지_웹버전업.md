# 2026-10-20 웹 버전 업데이트 때 세이브 초기화 수정 (LKH)

## 인계 블록
- **[목표]** 웹(itch.io)에서 새 버전을 올리면 세이브가 사라지고 새로 시작하던 문제를 고친다. 이미 세이브를 잃은 것처럼 보이는 사용자도 예전 진행을 이어서 할 수 있게 한다.
- **[현황]** 수정 완료·커밋됨(`8f0cc1a`). 로컬 웹 빌드로 버전 업데이트 상황을 재현해 확인함. 새 웹 빌드(`Builds/WebGL`, `Builds/MoreMustMush_WebGL.zip`, 이 수정 포함)가 만들어져 있음(git 제외 폴더). **itch.io 실제 업로드에서는 아직 확인 안 함.** 푸시 안 함.
- **[반환]** 사용자가 itch.io에 새 빌드를 올린 뒤 실제 이어짐 확인. 아래 "다음 세션 시작점".

## 다음 세션 시작점
1. `Builds/MoreMustMush_WebGL.zip`(이 수정 포함 빌드)을 itch.io에 올린 뒤, **그 전 버전에서 플레이하던 브라우저**로 열어 진행이 이어지는지 확인한다. 같은 브라우저·같은 itch 계정 상태여야 한다(다른 브라우저·시크릿 창은 저장소가 따로라 이어지지 않는다).
2. 이어지면 한 번 더 올려(다음 버전) 브라우저 사본 경로로도 이어지는지 확인한다.
3. 설정(언어·음소거·연출 간소화 등 PlayerPrefs)은 여전히 주소마다 따로다. 버전마다 설정이 초기화되는 것이 문제면 같은 방식(BrowserStore)으로 옮길지 사용자에게 묻는다.

## 원인
- 웹 빌드의 `Application.persistentDataPath`는 `/idbfs/<페이지 URL 해시>`다. itch.io는 올릴 때마다 게임 주소(`…/html/<업로드 번호>/index.html`)가 바뀌어 새 버전이 **빈 폴더**를 본다.
- 세이브(`save.dat`)와 암호 키 재료(`uid.txt`), PlayerPrefs가 모두 이 폴더 안에 있어 같이 안 보였다. 예전 데이터는 지워지지 않고 같은 브라우저 IndexedDB(`/idbfs`)의 다른 폴더에 남아 있다.
- 로컬에서 확인: v1 주소 → `/idbfs/de62f87d…/`, v2 주소 → `/idbfs/e8dc9b34…/`로 폴더가 갈렸다.

### 동작 (`SaveIO`)
- **저장**: 지금처럼 `save.dat`에 쓰고, 같은 암호 묶음을 `"uid:base64"`로 `localStorage`(`MoreMustMush.save`)에도 쓴다. 사본에 uid가 같이 있어 기기 ID가 바뀌어도 풀 수 있다. 사본을 쓰면 `MoreMustMush.legacyScanned = 1`.
- **불러오기**: 후보를 모아 **더 진행한 것**을 쓴다(`Ahead`: 플레이 시간 `play` → 판 수 `rounds` → 마지막 접속 `seenT`). 같으면 이 주소의 파일.
  1. 이 주소의 `save.dat`(+ `.tmp`·`.bak`)
  2. `localStorage` 사본
  3. **예전 버전 폴더**: `legacyScanned`가 없을 때 한 번만, `persistentDataPath`의 부모(`/idbfs`) 아래 다른 폴더들에서 `save.dat` + `uid.txt`를 찾아 그 uid로 푼다. 이 수정 전 버전에서 넘어오는 사용자용이다.
- 이 주소의 파일을 못 읽어도(손상) 사본·예전 세이브가 있으면 그것을 쓰고, 손상 파일은 예전처럼 `.bad`로 남긴다. 아무것도 못 읽으면 예전처럼 `LastLoadFailed`.
- `HasSave()`: 파일·예전 평문 PlayerPrefs·`localStorage` 사본·예전 버전 폴더 중 하나라도 있으면 true(메인 메뉴 '초기화' 버튼 표시).
- **초기화(`Wipe`)**: 파일과 함께 `localStorage` 사본을 지우고 `legacyScanned = 1`. 예전 폴더 세이브가 되살아나지 않는다.
- `PeekGold`(로그용 골드 미리보기): 파일이 없으면 사본을 읽는다.
- 웹이 아닌 플랫폼(Windows·Android·에디터): `BrowserStore`가 아무것도 안 해 동작이 예전과 같다.

## 확인한 것
- **에디터**: 기존 세이브를 그대로 읽음(스테이지 142, `LastLoadFailed` false). `Pack/Unpack` 왕복 정상, 다른 uid로는 풀리지 않음.
- **로컬 웹 빌드로 버전 업데이트 재현** (`python -m http.server`, 같은 사이트 `localhost:8790`의 서로 다른 경로 = itch가 업로드마다 주소를 바꾸는 상황):
  - v1 = 이 수정 **전** 빌드(10-16), v2·v3 = 이 수정 빌드.
  - v1에서 3스테이지·29G까지 진행 → **v2에서 그대로 복구**(예전 폴더 찾기). 기기 ID도 v1과 같게 이어짐(`20e39d6c…`).
  - v2에서 첫 노드 구입(17G) → `localStorage`에 사본(약 2KB)·uid·`legacyScanned` 생김 → **v3에서 v2 진행 그대로**(사본 경로).
  - v3에서 초기화 → 사본 지워짐 → 다시 열면 새 게임('초기화' 버튼 없음). v1·v2 폴더의 세이브가 되살아나지 않음.

## 확인 못 한 것·주의
- itch.io 실제 업로드(주소 형식 `html.itch.zone` 등)에서는 확인 안 함. 원리는 같다(같은 사이트, 다른 경로).
- 같은 브라우저의 같은 사이트 저장소일 때만 이어진다. 다른 브라우저·기기·시크릿 창·사이트 데이터 삭제 뒤에는 이어지지 않는다(서버 저장이 없다).
- 예전 주소(이전 버전 탭)를 다시 열어 플레이하면 그 폴더의 세이브를 쓰고, 이 수정 전 빌드라면 `localStorage`를 갱신하지 않는다. itch에서는 예전 주소로 다시 들어갈 일이 거의 없다.
- PlayerPrefs 설정(언어·음소거·효과음/배경음 크기·연출 간소화)은 주소마다 따로라 새 버전에서 기본값으로 돌아간다.
- `localStorage`는 사이트당 약 5MB를 다른 itch 게임과 같이 쓴다. 세이브 사본은 지금 약 2KB(진행이 많은 세이브도 수십 KB 수준). 쓰기에 실패하면 사본만 빠지고 파일 저장은 그대로 된다.

## 웹에서 직접 확인하는 법 (다음에 다시 볼 때)
- 브라우저 개발자 도구 콘솔:
  - `Object.keys(localStorage).filter(k => k.startsWith('MoreMustMush.'))` → `uid`·`save`·`legacyScanned`가 있어야 한다.
  - IndexedDB `/idbfs` → `FILE_DATA`의 키에 주소별 폴더(`/idbfs/<해시>/save.dat`)가 보인다.
- 웹 빌드: Unity 메뉴 `MoreMush/Build/WebGL (itch.io)` (약 6분, 끝나면 Windows 대상으로 돌아감). MCP로 부르면 응답이 시간 초과로 끊기지만 빌드는 계속된다(`Logs/webtest_build.txt`처럼 결과를 파일로 남기면 확인이 쉽다). `EditorApplication.delayCall`로 예약하면 실행되지 않은 적이 있다.
- 로컬 테스트에서 공 발사: 브라우저 자동 클릭(드래그)은 누름·뗌이 같은 프레임이라 발사되지 않는다. 캔버스에 `pointerdown → pointermove 여러 번 → pointerup`을 시간 간격을 두고 보내면 된다. 브라우저 창이 숨겨져 있으면 게임이 매우 느리게 돈다.
