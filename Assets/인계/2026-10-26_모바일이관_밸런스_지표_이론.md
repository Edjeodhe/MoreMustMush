# 모바일 이관용 — MoreMustMush 재화 밸런스: 지표·원칙·이론·측정 결과 (2026-10-26)

> 이 문서 한 개만 받는 '모바일' 프로젝트 에이전트용이다. 원 게임(Unity, MoreMustMush, 브랜치 KHD, 커밋 b1e77c2a 기준)의 코드·씬·DB를 못 본다는 전제로, 필요한 표·공식·상수·결정은 모두 여기에 옮겨 적었다. 괄호 안 경로는 출처 표기일 뿐이다(열어 볼 필요 없음). 출처 없는 수치는 쓰지 않았고, 추정은 '추정', 모델 계산은 '모델값'으로 표시했다.
>
> 표기: **내부 판** = 튜토리얼을 포함한 판 번호(코드의 `G.stage`). **표시 스테이지** = 화면 번호 = 내부 판 − 튜토리얼 판 수. 튜토리얼은 **지금 2판**(2026-10-23부터, 그전 10-20~10-23은 4판). 이 문서의 표는 가능한 한 **표시 스테이지**로 적고, 옛 문서가 내부 번호로 적은 곳은 "(옛 내부 n, 튜토리얼 4판 기준)"을 병기한다.
> 판 = 라운드 1회. 분 = 누적 플레이 시간. 봇 = 에디터 봇 시뮬. 사람 = D1 실사용 지표 또는 사람 모델.

## 0. 이 문서 사용법과 읽는 순서

### 0-1. 에이전트용 5줄 요약
1. 게임은 "수확기(공)를 슬라이드 바로 튕겨 버섯 군락을 부수고, 점수를 골드로 바꿔 균사 트리 노드를 사는" 판(라운드) 반복형 인크리멘탈이다. 10스테이지마다 보스(5종 순환)가 허들이다.
2. 밸런스 판단의 근거는 **D1 실사용 지표(보스 퍼널·판별 획득·이탈)** 이고, 봇 시뮬은 "가격·수입 곡선과 DPS 비"만 재는 도구다. 봇은 보스를 사람보다 5~40배 잘 잡으므로 보스 체력을 봇 도전 수로 맞추면 안 된다.
3. 수치는 노드 이름이 아니라 **노드 무관 목표 곡선**(표시 n에서 판 수입 배율·판당 구매 수·다음가/판 수입·보스 실패율·허들 분)으로 남긴다. 새 노드 배치는 이 곡선을 맞추도록 가격·효과를 정한다(2절·4절).
4. 사용자 결정의 뼈대: 초반은 즉각 성장(판당 ×1.5), 표시 10·20 보스는 쉬운 허들, 무한 노드는 덧셈, 후반(표시 60~)은 "파밍하며 강해져 넘는 시간 허들(10~20분, 뒤로 갈수록 길게)", 실패 체력 감소 대신 끈기, 세계수가 후반 주 성장 축.
5. 작업 방식: 조사(원칙) → 이론(Opus) → 독립 검증(Opus) → 적용(관리자, 코드·DB 같은 빌드) → 봇 측정(Sonnet) → 재검증 → 사용자 확인 뒤 커밋. 사용자 몫(목표 시간·구조 변경)은 멈추고 묻는다.

### 0-2. 핵심 결론 10줄
1. 초반 이탈 1위는 내부 판 1~2(27명 중 9명, 33%)이고, 원인은 가격이 아니라 "첫 강화가 화면에 아무 변화도 안 줌"이었다 → 첫 판 뒤 수입을 올리는 구매 2개를 살 수 있게 했다(8회차).
2. 판당 판 수입 배율 r = m^n(m = 구매 하나의 수입 배율, n = 판당 구매 수). 초반 ×1.5를 내려면 m ≈ 1.2에서 n ≈ 2.2, 싼 노드의 2/3 이상이 m ≥ ×1.1이어야 한다.
3. 보스 체력 식(노드 무관): Hp = D⁻¹ × 사람 유효 DPS × (판 시간 − 2). 사람 실패율은 로그정규 ln D ~ N(mu, s)로 D1 실패율·남은 HP에 맞춘다.
4. 첫 바퀴 보스 목표 사람 판당 실패율: 표시 10·20 ≤ 15%, 30 ~40%, 40 ≤ 50%, 50 50~60%. 값은 D1 새 빌드로 다시 맞춘다.
5. 무한 노드는 효과 덧셈(1 + step·L)·가격 곱. 곱이면 레벨 129에서 공격력 ×6,610처럼 폭주했다.
6. 덧셈 싱크만으로는 "파밍 1판 힘 증가"가 ×1.02~1.04에 머문다(구조 한계). 그래서 판 수에 직접 묶인 곱 축 **끈기**(2점마다 보스 피해 ×1.05, 상한 ×3)를 넣었다.
7. 후반 허들 목표(사람, 세계수 없음 기준 평균): 표시 60 4분 · 70 10 · 80 14 · 90 16 · 100 20분, 60분 넘게 막히는 사람 ≤ 5%. 사람 표시 100 도달 약 190분(세계수 4단계, 모델값).
8. 10-23 기준선(옛 트리, 봇 SKILL 0.6): 표시 60·80·100 도달 63.7·87.1·111.5분, 보스 60~100 전부 첫 도전.
9. 새 균사 트리(Test_JS2) 이식 it3: 초반(표시 10·20·30 = 8·15·23분)은 같지만 표시 100 도달 1,017~1,124분(약 10배 느림), 90·100 보스 벽, 중반 판 수입 1/10~1/20. 원인은 보스 피해 몫·중반 수입 칸 공백·늦은 싱크 열림.
10. 모바일로 가져갈 것은 2절 지표, 3절 원칙·결정, 4절 모델 꼴, 5절 측정 방법론이다. 6·7절의 현재 노드 값은 참고용이다.

### 0-3. 읽는 순서
- 처음: 0 → 1(게임) → 1.5(재화 구조) → 2(지표, 핵심) → 3(원칙·결정).
- 수치 세울 때: 4(이론) → 7(현재 상수) → 8(열린 문제).
- 측정기 만들 때: 5(방법론) → 9(팀 지시문).
- 결과 대조: 6(회차별 결과·기준선).
- 불일치·미확인: 부록 A, 검증 체크리스트: 부록 B.

### 1-3. 점수 → 골드 정산
- 점수는 **타격마다** 준다(안 죽어도 들어옴): 점수 = 등급 점수 × 점수 배율 × (치명 ? 치명 배율 : 1) × (보스 ? 0.05 : 1). (`RoundSim.Balls.cs:333-334`)
- 점수 배율 = (1 + `ed_hunt` + 별·세트) × 지역 배율 × (1 + 콤보 × 콤보 계수 × 피버 보정) × 황금 ×10 등. (`Game.cs:263`, `RoundSim.Balls.cs:300-314`)
- 콤보 계수 = (0.1 + 별 몫) × (1 + `ps_combo`). 피버: 연쇄 25 이상 ×1.5, 70 이상 ×2(1.5초 끊기면 리셋). (`Game.cs:260`, `Defs.World.cs:109-134`)
- 치명 배율 기본 3.0(줄 Lv0 2.0 + 1), 구매 시 3.5·4·5. (`Game.cs:259`, db.json)
- **정산 골드 = floor(점수 × goldMul)**, goldMul = (1 + 정산 보너스 + 세계수 가호) × 끝없는 풍년(1 + 0.04L) × 세계수 골드 보정(1 + 0.12 × (세계수 단계 − 1)). 정산 보너스 = `ed_haggle` + `ed_regular` + 0.1(고정) + 별. (`Game.cs:200-201,297`)
- 판매·의뢰 수입은 **없다**(삭제). 일일·주간 의뢰 보상은 세계수 경험치뿐. (`Game.Shop.cs:8`, `Defs.Quests.cs:19-31`)
- 보스: 지면 그 판 골드 ×0.8. 이기면 추가 골드 = max(이번 판 골드, 직전 일반 판 골드) × 2 + 균사석. (`RoundSim.Effects.cs:444-448`, db.json)

### 2-2. 판 수입 배율 (구간별 판당)
- **정의**: 일반 판 net의 판당 기하 배율. 판 편차가 커서(같은 구성에서도 ×10) 5판 중앙값 또는 구간 기하평균으로 잰다. 보스 판 제외. (`조사.md` P6·P6')

## 4. 이론

### 4-1. 판 수입 모델
- 회귀 꼴(8회차): **ln net(n) = FE(n) + Σ b_k ln x_k**. x = 타격 점수(등급 기본 + 고정값)·정산 배율·판 시간·군락 수·zoom·콤보(1 + 5·comboK)·영구 수확기·바·장치·재생·희귀·꼬마·크기·속도·1단계 스킬. FE(n) = 판 n의 노드 밖 몫(종 수·낱개·초반 체력·도감 별·피버). (`이론_8.md` 1-1)
- 측정 탄력 b(판 수입 ∝ x^b): 점수 1 · 정산 1 · 판 시간 0.8(0.60~1.06) · 군락 수 0.7(0.61~0.78) · zoom 1.0 · 콤보 1 · **영구 수확기 1.04(0→1개 ×2.06, T8-1)** · 바 0.3 · 필드 넓히기 ≈ ×0.9~1.0(군락+와 밀도−가 상쇄). 3회차 실측: 군락 수 지수 0.74~0.77(1~12개, 6~12개 포화 0.2~0.35). 초반 그루터기 ×1.53(10초 판)·×2.00(17초 판). (`이식_8.md` 1절, `이론_8.md` 1-1, 하위 조사 `테스트.md` T3-α)
- 오차: 시드 사이 RMSE(ln) 0.349(판 하나 ×1.42). (`이론_8.md` 1-1)
- **골드 = 타격 점수 × 정산** 구조라 점수·정산 노드는 탄력 1이다. 공격력은 초반(버섯이 한 대에 죽음)엔 수입에 거의 안 듣는다. 바다(9회차)에선 판 수입의 공격력 탄력 EF ≈ 0.02 — **공격력은 보스에게만 듣는다**. (`이론_8.md` 1-2, `이론_9.md` 9-R-1)
- 새 트리 수입 배율: G = (1 + ed_hunt) × (1.1 + ed_haggle + ed_regular). 일반 판 net ≈ H(P) × G × 지역 × 공 수 × 판 시간, H = 노드로 설명 안 되는 몫(산 최고가 P별 실측: 1e3 30 → 1e6 290 → 1e7 1,300 → 1e10 8,300). 옛 net에 닿으려면 G가 표시 10 약 100·25 400·50 2,600·70 8,300. (`이론_9m.md` A·B절)

### 4-4. 보스 체력 모델
**(가) 첫 바퀴: 사람 D 분포 맞춤 (8회차)**

### 4-5. 허들·끈기 모델
- **왜 골드 싱크로는 시간 허들이 안 되나**: 효과 덧셈·가격 곱이면 파밍 1판 성장 ≈ (한 판 수입 ÷ 싱크 누적 지출) ÷ ln(누적 ÷ 시작가). 효과 크기·가격비와 거의 무관. 측정: 파밍 1판 D 60 ×1.023·70 ×1.024·80 ×1.12·90 ×1.036·100 ×1.025 → 목표 ×1.04는 80만. 가격비를 ×1.03으로 내려도 ×1.03 안팎. 세계수 단계 보스 공격력은 단계마다 한 번 오르는 고정 이동이라 "지고 → 파밍 → 강해짐"을 못 만듦. (`이론_9.md` 9-R4-2, 9-R5-0)
- "끝이 보이는 허들"이려면 파밍 1판에 보스 힘 +6% 이상(9-R2: 사람 흔들림 ln D 0.70에서 약한 10%가 +20분 안에 따라잡는 조건). 덧셈 싱크는 30~40판 뒤 +1% 아래. → 판 수에 직접 묶인 곱 축 = 끈기. (`이론_9.md` 9-R2-1, 9-R2-6)
- **진 판 몫 0.5 근거**(파밍 판 = 1): 몫 0이면 계속 재도전하는 사람 47.6%가 100에서 60분+ 막힘, 몫 1이면 세계수 4단계에서 파밍 2판이 바로 재도전보다 5분 늦음(파밍 이득 사라짐). 0.5는 둘 다 지킴(4단계 0판·2판 모두 190분). (`이론_9.md` 9-R5-1)
- 끈기를 끄면(같은 체력) 100 도달 231분, 70 막힘 11%·100 막힘 21% → **이 체력은 끈기가 있어야 성립**. (`이론_9.md` 9-R5-3)
- 민감도(세계수 없음): 판 흔들림 σ 0.40이면 막힘 6.8%, 수입 ×0.5면 13.4%(세계수 4단계 8.4%), 스킬 몫 W 0.25면 11.8%, W 1.0이면 0.5%·182분. 가장 큰 불확실성 = 사람 수입(0.6배 가정)과 W. 실측 q로 mul × exp(0.70·(z(목표) − z(q))) 재보정. (`이론_9.md` 9-R5-4)

### 5-2. 실제 게임과의 차이
- 봇은 보스를 직접 겨누고 스킬이 다 있어 **보스 DPS가 사람의 5~40배**. 봇 도전 수·처치율로 체력을 맞추지 않는다. 봇은 **DPS 비**(스킬 있음/없음, 상태 A/B)만 잰다. (`이식_8.md` 2절)
- 봇은 세계수·보따리·꼬마를 안 쓴다 → 세계수 몫 따로 모델링. (`이론_9.md` 9-R-4)
- 봇은 반응 지연·집중 끊김이 없다(넣을지 사용자 결정 보류 이후 lag 근사로 대체). (`요약_밸런싱_DB.md` 4절)
- 사람/봇 판 수입 비는 구간마다 다르다(0.025~0.65, 2-1). 한 값(0.2·0.6)으로 외삽하면 틀린다.
- 봇 한 판 1.16분 vs 사람 1.35분. (`이론_9.md` 2절)

### 5-5. 사람 vs 봇 보정 요약
1. 사람 분포는 D1(실패율·남은 HP)로 맞춘다 — 유일한 사람 근거.
2. 봇은 비율(DPS 비, 유도 배율 M, 스킬 몫 W, 수확기 탄력)과 곡선 모양만.
3. 사람 상태(R)는 봇 비로 대리하되 가정으로 표시하고 D1 #2(보스 도전 유저의 업그레이드 레벨)로 확인.
4. 후반은 c 모델(어려운 쪽) → 틀리면 쉬운 쪽으로 틀림.
5. 표본이 작으면(27~38명) "참고용"으로 쓰고 결론 방향만 본다. (`이론_8.md` 3-2, `이론_9.md` 9-R2-2)
