# 2026-10-19 AdMob 보상형 광고 밑작업 · 플랫폼 방침

## 인계 블록

- **[목표]** 모바일 수익화용 AdMob을 붙인다. 이번에는 SDK 설치 상태를 확인하고 보상형 광고 코드 밑작업만 한다.
- **[현황]**
  - Google Mobile Ads 플러그인 11.6.0 설치(`Assets/GoogleMobileAds`, `Assets/Plugins/Android·iOS`), EDM은 패키지 `com.unity.external-dependency-manager 2.1.0`.
  - "ExecuteMenuItem target for External Dependency Manager does not exist"는 패키지 추가 직후 메뉴 등록 전이라 난 것이었다. 에디터를 재시작하자 Android Auto-Resolution 창이 떴고 사용자가 Resolve를 눌렀다.
  - 앱 ID는 사용자가 GoogleMobileAds 설정에 넣었다(`Assets/GoogleMobileAds/Resources/GoogleMobileAdsSettings.asset`).
  - `Core/Ads.cs`를 새로 만들고 `App.Awake`에서 `Ads.Init()`을 부르게 했다. csharp 검토에서 지적된 HIGH 1건(Show 예외 시 소리·상태 묶임)을 반영했다.
  - **컴파일 미확인**: Unity MCP 연결이 끊겨 콘솔을 보지 못했다. 기기 테스트도 아직 안 했다.
- **[반환]** 광고 버튼 위치·보상 내용이 정해지면 버튼을 붙인다. 웹 데모 범위가 정해지면 데모 제한을 넣는다.

## 다음 세션 시작점

1. Unity 콘솔에서 `Ads.cs` 컴파일 에러가 없는지 확인한다(빌드 대상 Android·WebGL 둘 다).
2. 광고 버튼 위치와 보상을 정한다(예: 정산 화면 골드 2배). 보상 수치는 밸런스 팀으로 정한다.
3. 안드로이드 Development Build로 테스트 광고가 뜨는지 확인한다. 에디터에서는 가짜 광고만 나온다.
4. 출시 전에 `Ads.cs`의 `REWARDED_ANDROID`(·`REWARDED_IOS`)에 AdMob 콘솔의 광고 단위 ID를 넣는다.
5. 웹 데모 범위(몇 스테이지까지)를 정하고 `#if UNITY_WEBGL`로 제한과 "모바일에서 계속" 안내 화면을 만든다.

## 이번에 한 것

| 곳 | 내용 |
|---|---|
| `Core/Ads.cs` (새) | 보상형 광고. `Init`(SDK 시작, 콜백을 메인 스레드로, 미리 불러오기), `RewardedReady`, `ReadyChanged` 이벤트, `ShowRewarded(onReward, onFail)`. 콜백은 광고가 닫힌 뒤 한 번만 온다. 불러오기 실패 시 5·15·30·60초 뒤 재시도. 광고 중 `AudioListener.pause`. 안드로이드·iOS 밖(WebGL·PC)은 `#if`로 빠지고 늘 준비 안 됨 |
| 광고 ID | 개발 빌드·에디터, 또는 진짜 ID가 비어 있으면 구글 테스트 ID(안드로이드 `ca-app-pub-3940256099942544/5224354917`). 진짜 ID로 테스트하면 계정이 막힐 수 있다 |
| `Flow/App.cs` | `Awake`에서 `Ads.Init()` |

쓰는 법:

```csharp
if (Ads.RewardedReady)
    Ads.ShowRewarded(() => { /* 보상 */ }, () => { /* 실패·중간에 닫음 */ });
```

## 사용자 결정

- 모바일이 주력이고 보상형 광고로 수익을 낸다.
- itch.io 웹은 데모다. AdMob은 웹을 지원하지 않아 광고가 없다. 웹 광고를 원하면 CrazyGames·Poki 같은 포털 SDK가 현실적인 길이다(지금은 안 함).
- 웹 세이브를 모바일로 옮기지 않는다. 서버 비용을 더 쓰지 않으려고 모바일은 새로 시작한다. 로그 서버(Cloudflare Worker)는 받기 전용 그대로 둔다.

## 남은 것 / 주의

- 앱이 광고 화면으로 넘어가면 안드로이드에서 `OnApplicationPause`가 와서 저장한다. 광고가 10분(`HARV.returnMin`)을 넘을 일은 없어 복귀 창은 뜨지 않는다.
- 검토 LOW: `App.I`가 없을 때 불러오기에 실패하면 재시도가 걸리지 않는다. 실제로는 초기화 콜백이 App이 생긴 뒤에 와서 문제가 없다.
- 전면·배너 광고, 유럽 동의 창(UMP)은 아직 없다. 유럽 출시 때 UMP가 필요하다.
- 이번 커밋에서 뺀 것: `Assets/Scenes/MainMenu.unity`(카메라 URP 데이터·뷰포트 변경)와 `Assets/Fonts/GowunBatang-Bold Wood.mat`(TMP가 다시 계산한 값). 이번 작업과 상관없는 변경이라 그대로 두었다.
