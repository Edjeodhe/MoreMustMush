## 바뀐 것

### 클라이언트 (`Assets/Scripts/Core/Telemetry.cs` 외)
- **세계수**: 진입(`FTUE_FIRST_TREE`)을 `OutGameController.Start`에서 기록. 세계수 화면에 있는 동안 세계수 로그(`tree_up`·`tree_build`·`tree_act`·`quest_clear`)를 모아 기기 파일(`logtree.dat`)에 저장, 반복 레벨업(ring·klv_·deco_)과 같은 `tree_act`는 한 줄로 합침(`c` 횟수·`lv0` 첫 레벨·합계/마지막 값), 화면을 나갈 때 한 번에 전송
- **새 로그**: 꼬마 레벨업 `klv_<꼬마>`, 장식 강화 `deco_<장식>`, `tree_act`(공물 tribute·선물 gift·즉시 완료 craft_rush)
- **스테이지**: 1~20은 판마다. 21부터 보스 구간(21~30 …) 클리어를 모아 보스 클리어 때 한 줄(`stage0`·`score0`·`c`, 합계는 잔액 공식이 그대로 맞음). 보스 실패·중도 포기는 모으던 구간을 먼저 보내고 그 판만 따로. 엔딩 뒤(`G.ending`)는 세션 동안 한 줄로 합쳐(`post`·`nf`) 뒤로 갈 때만 전송. 모을 때 eid·세션·버전을 정해 둬서 다시 보내도 중복 저장 안 됨
- **전송 시점**: 접속 직후·FTUE 1·2단계·스테이지 종료·세계수 나갈 때 + 앱이 뒤로 갈 때 그 자리에서(`Background` → `SendNow`, 웹은 `sendBeacon`). 보낸 항목은 값으로 지움
- **웹 전용**: `Assets/Plugins/WebGL/MMMTelemetry.jslib` (sendBeacon, visibilitychange·pagehide, localStorage 실행 표시)
- **FTUE**: 2~5단계는 그 기기에서 1단계를 보낸 경우만, 기록 즉시 저장
- **기타**: 버전 0.0.7, 세이브를 못 읽어 새로 시작할 때 `ResetSnap`
- 확인: Unity 컴파일 OK, WebGL 조건 스크립트 컴파일 OK(웹 전용 멤버 포함). jslib는 실제 웹 빌드에서만 끝까지 확인됨

### 서버 (`Server/`)
- `worker.js`: `tree_act` 허용, 모르는 이벤트는 그 건만 건너뜀, 이상치(섞인 uid·eid가 세션으로 시작 안 함·범위 밖 c/stage0/step/lv)는 저장하지 않고 `suspect`에 uid·사유, IP당 요청 제한(`MMM_LIMIT` 60초 60번, 넘으면 429 → 클라가 나중에 재전송)
- 배포: **wrangler** (`cd Server && npx wrangler deploy`). 앞으로 대시보드 붙여 넣기와 섞지 말 것. `wrangler.toml`에 D1 ID·요청 제한·`preview_urls = false`. 로그 키는 secret `MMM_LOG_KEY`
- WAF 요청 제한 규칙은 workers.dev 주소에 못 건다 (자기 도메인 전용) → 워커 안 Rate Limiting 바인딩으로 대신함
- D1 인덱스: `i_logs_event_cts(event, cts)`, `i_stage_cts(cts)`. 하루치 조회가 약 5,600행 → 약 200행
- `queries.sql`: 모든 쿼리 최근 7일·cts(기기 시각)·한국 날짜, 조인 대신 uid별 플래그 집계(FTUE 퍼널 29만 행 → 3천 행), 세계수 진입 = 5단계 또는 세계수 로그, 꼬마 보유 = 구매·강화·각성 중 하나, 재화 검사에서 새 게임·큰 수 오차 제외, 엔딩 뒤 최종 스테이지(17번)

## 정합성 점검에서 나온 것 (데이터 기준, 10-15~10-20 웹)
- 웹 crash 대부분이 오탐(재접속 세션 38%가 crash로 시작) → 0.0.7에서 고침. 그 전 crash 지표는 노이즈
- 짧게 하고 떠난 유저 로그가 늦게 오거나 안 옴(session_start 42행 10분 넘게 지연) → 뒤로 갈 때 즉시 전송으로 줄임
- 세션 길이는 탭을 띄워 둔 시간까지 들어감 → 쿼리 10번은 5분 넘는 빈틈을 뺀 활동 시간
- 큐 넘침·중복·스테이지 건너뜀은 0건 (문제 없음)
- 신규 퍼널(최근 7일): 첫 실행 310 → 새 게임 261 → 첫 발사 243 → 첫 판 끝 239 → 첫 업그레이드 169(여기서 29% 이탈). D1 복귀율 0~10%로 낮음

## 사용자 결정
- D1은 따로 요청이 없으면 **최근 7일만** 읽는다 (메모리 `d1-read-7days`)
- 로그는 행 수를 줄이는 쪽(묶음·합치기)으로. 단 FTUE 단계 합치기는 시작 이탈 분석 때문에 하지 않음
- 접속(session_start·crash)은 원래 방식 유지. 세션 종료 로그는 넣지 않음
- 웹 출처(Origin) 확인은 하지 않음
