# 2026-10-21 모바일 버벅임 최적화 · 테스트용 개발자 모드 (LKH)

## 인계 블록
- **[목표]** 사용자가 APK를 안드로이드 에뮬레이터(가상 OS)로 돌려 보니 "플레이 불가능할 정도로" 버벅였다. 메모리 사용량과 연산량을 줄이고, 모바일 테스트용으로 버튼 하나로 골드를 늘리는 개발자 모드를 넣는다.
- **[현황]** 아래 작업 전부 **커밋됨** (`ce2a75c`, 사용자가 커밋, 작업 트리 깨끗). 측정은 전부 PC 에디터 값이다. **APK 빌드·에뮬레이터 확인은 사용자가 하는 중**이고 결과는 아직 못 받았다.
- **[반환]** 남은 일은 맨 아래 "남은 일". 앞 세션 질문이었던 "회전 칼날을 안 찍어도 발동" 버그는 원인을 못 찾고 사용자 지시로 조사를 멈췄다(아래 "회전 칼날 조사").

## 다음 세션 시작점
1. 사용자에게 에뮬레이터 결과를 묻는다: 어디서 끊기는지(시작·라운드·세계수·밤 테마), 에뮬레이터 이름. 그에 따라 아래 "남은 일" 1~3 중 고른다.
2. 에뮬레이터에서 계속 버벅이면 Graphics APIs 순서(Vulkan → OpenGLES3 우선)부터 바꿔 본다. 코드보다 먼저.
3. 출시 빌드 전에는 `MMM_DEV` 정의를 반드시 뺀다(아래 2).

## 한 일

### 1. 모바일 텍스처 압축 (가장 큰 원인)
- 아틀라스 26장 전부 플랫폼 설정이 Default·Standalone·WebGL = **DXT5뿐**이었다. 안드로이드·iOS 덮어쓰기가 없어 모바일 GPU(DXT 미지원)가 실행 중에 RGBA32로 풀어 올린다 → 메모리 4배 + 불러올 때 끊김.
- `SpriteDB`(`Resources/SpriteDB`)가 그림 1,425개를 한 번에 참조해서, 첫 접근 때 아틀라스 41장(버섯 4096 한 장 포함)이 **전부** 메모리에 올라온다.
- 계산(기준 해상도, 밉 없음): DXT5 약 134MB → 안드로이드 실제 약 540MB(RGBA32) → **ASTC 6x6 약 60MB**.
- `Assets/Editor/ProjectOptimization.cs`
  - `BuildAtlases()`가 아틀라스를 만들 때 Android·iPhone에 ASTC 6x6(CompressedHQ, 최대 크기는 기존 `AtlasMaxSize`)을 같이 건다.
  - 새 메뉴 `MoreMush/Optimize/Mobile Texture Compression`: 아틀라스를 다시 묶지 않고 지금 아틀라스 26장 + 아틀라스 밖 그림(`FX/brush`·`FX/square`·`FX/tree_soil`)에만 모바일 압축을 건다. 이번에 실행함(29개). `tree_soil`은 1672×941 NPOT이라 PC에서도 RGBA32(12MB)였다.
- 에디터 빌드 대상은 Standalone이라 PC 화면은 그대로다. ASTC 압축은 APK 빌드 때 처음 일어나서 첫 빌드가 오래 걸린다.

### 2. 그림자 끄기
- `Mobile_RPAsset`·`PC_RPAsset`의 `m_MainLightShadowsSupported`·`m_AdditionalLightShadowsSupported` → false. 씬에 Directional Light(Soft 그림자)와 2048 그림자 맵이 잡혀 있었다. 스프라이트 게임이라 쓰지 않는다.
- `ProjectOptimization.ConfigureSettings()`(메뉴 Player and Render Settings)에도 같은 줄을 넣어 다시 돌려도 유지된다.
- 확인한 것: Mobile 품질은 HDR·MSAA 꺼짐, 기본 볼륨(Bloom 등)은 세기 0이라 문제 아님.

### 3. 매 프레임 할당·연산 (프로파일러 GC.Alloc 호출 스택으로 찾음)
| 화면 | 프레임당 할당 | 스크립트 시간 |
|---|---|---|
| 세계수(OutGame) | 7.7KB → 0.3KB | `FarmView.Update` 0.52 → 0.06ms |
| 라운드(Stage, 게임 코드) | 약 1.8KB → 0.34KB | `StageController.Update` 약 0.6~0.9ms (그대로) |
| 업그레이드(MainGame) | 0 → 0 | `TreeView.Update` 0.46 → 0.24ms |

- **세계수**: `FarmTreeView.Growth`가 슬롯마다 매 프레임 `KidsIn()`(LINQ 리스트)을 2번, `KLvSteps()`는 `Count` 람다 안에서 원소마다 `KLvSum()`(또 LINQ)을 돌렸다.
  - `Game.Farm.cs`: `KLvSum`·`KLvSteps`를 루프로, 새 `KidsInCount(zone)`·`KidIn(kid, zone)`(리스트 없이). `ZoneRoom`·`GrowMul`·`Growth`가 이것을 쓴다. 결과는 같다.
  - `FarmTreeView.Layout()` 키: 문자열 보간 → 정수 튜플 `(Stage, MushSlotCount, DecoSlotCount, Ring)` + `laidOut`.
- **라운드**: `ShroomView.PlaceBody`의 `Mathf.Max(a, b, c)`가 `params float[]`를 만들어 버섯마다 매 프레임 44B → 둘씩 비교. (같은 패턴이 `SettleScreen.cs:160`에 있지만 한 번만 불려 둠.)
- **업그레이드 화면**: `TreeNodeView.Draw`가 노드 108개의 Transform 크기 4개·`Show`·`Art.FitPx`를 매 프레임 썼다 → `dirty`(상태·호버·라벨·언어 변화)일 때만. 옛 그림 세트(slot == null) 경로는 그대로.
- 작은 것들
  - `BallView`: 몸통 그림이 같으면 다시 넣지 않음.
  - `App.InGame`: `Scene.name`(매번 새 문자열) → 활성 씬 handle이 바뀔 때만 이름 확인(`OnMainMenu`).
  - `Game.QuestClaimableCount`: `Concat().Count(람다)` → 루프(업그레이드 화면 매 프레임).
  - `CritterRig.Evo`: 얼굴 키 문자열 이어붙이기 → `SpriteDB.Key(l.face ?? "", ...)` 캐시.
  - `WeatherOverlay`: 밤·보름달 가림막 셰이더(`WeatherMask`)가 화면 전체 픽셀마다 구멍 수(최대 65)만큼 돈다 → **모바일만** 구멍 12개(`MOBILE_HOLES`). 바 구멍을 맨 앞에 두고 공은 리스트 앞(영구 수확기)부터. PC는 그대로.
- 조사 에이전트(Explore)가 낸 목록 중 안 고친 것: 아래 "남은 일" 4.

### 4. 테스트용 개발자 모드 (`Assets/Scripts/Flow/DevMenu.cs`)
- 모든 씬 왼쪽 가장자리(왼쪽 가운데 기준 x 70, y −260)에 빨간 **DEV** 버튼. 누르면 패널: **골드 ×10**(늘어나는 양이 100만보다 적으면 100만), **골드 +100만**. 누르면 바로 `SaveGame()`, 알림 띠에 "[DEV] 골드 +…".
- `RuntimeInitializeOnLoadMethod(AfterSceneLoad)`로 스스로 생기고 `DontDestroyOnLoad`, 자기 Overlay 캔버스(sortingOrder 32000)라 팝업 위에서도 눌린다. 버튼 그림은 `TempDialog.SkinButton`.
- **`#if UNITY_EDITOR || MMM_DEV`** 안에만 있다. 이번에 Android·Standalone Scripting Define Symbols에 `MMM_DEV`를 넣었다(`ProjectSettings.asset`). **출시 빌드에서는 빼야 한다.**
- 확인: 플레이 모드에서 골드 591,919 → 5,919,190, 패널 화면 확인. 테스트는 `SaveIO.Suspended`로 저장을 막고 해서 세이브는 그대로다.

### 5. 그 밖에 답한 것
- 버섯은 이미 프리팹 1개(`ShroomView.prefab`) + 풀(`Pool<ShroomView>`, 200개 미리 생성)이다. 프리팹을 종류별로 나눠도 메모리는 안 준다(메모리는 텍스처가 차지).
- 버섯 충돌은 Unity 물리를 안 쓴다(`Collider`·`Rigidbody` 0개). `RoundSim`의 원 거리 계산 + 격자(`RebuildGrid`·`QueryCircle`)라 메모리 영향 없음.
- APK 하나로 단독 실행됨: Split Application Binary 꺼짐, AAB 꺼짐, StreamingAssets 없음, minSdk 25. 서버 로그는 오프라인이면 기기에 쌓아 둔다. 구글 플레이용은 Build App Bundle을 켠다.

### 회전 칼날 조사 (미해결, 사용자가 중지)
- 증상(사용자): 회전 칼날 노드를 안 찍었는데 **공 주위에 칼날 고리**가 보였다.
- 고리 = `BallView.prefab`의 `Blade`(그림 `FX/ring_thin`, 프리팹에선 켜진 채 저장). `BallView.Show`가 매 프레임 `st.blade || b.hv == "mill"`로 켜고 끈다.
- 켜지는 길은 둘뿐: 노드 `bl` 레벨 > 0(`Game.ComputeStats` `st.blade`), 갈아내기 수확기 `mill`(분열 소형도 `b.hv`를 이어받음).
- 지금 PC 세이브: `bl` 0, 수확기 `sam`·`gold`, `ComputeStats` 결과 `st.blade=False`. 노드 레벨을 바꾸는 곳은 구매·세이브 변환·에디터 봇 `BulkBuy`뿐.
- 의심: 다른 세이브(웹 빌드·초기화 전), 갈아내기 수확기를 잠깐 낀 판, 또는 칼날이 아닌 다른 고리. 사용자에게 스크린샷·빌드 종류를 물었고 답 없음.

## 작업 요령·주의
- **측정 방법**: 플레이 중 `ProfilerDriver.enabled = true`, `Profiler.enableAllocationCallstacks = true` → `ProfilerDriver.GetRawFrameDataView`에서 `GC.Alloc` 샘플의 `GetSampleCallstack` + `ResolveMethodInfo`로 MoreMush 함수별로 묶었다. 스크립트 시간은 `Assembly-CSharp.dll!` 샘플 합.
  - `GC.GetAllocatedBytesForCurrentThread()`는 Unity Mono에서 늘 0이라 쓸모없다. `Profiler.GetMonoUsedSizeLong()` 차이는 된다.
- **라운드를 띄울 때 세이브 보호**: `SaveIO.Suspended = true` 뒤 `RoundFlow.Request()` → `RoundSim.R.Launch(각도)`. 판이 끝나면 `RoundSim.Finish`가 저장하므로 **먼저 막아야 한다.** 끝나면 `Suspended = false`로 돌려놓는다(도메인 리로드를 안 하면 플레이 사이에 남는다).
  - 이번 세션 초반 회전 칼날 확인 때 막지 않고 한 판을 돌려 **한 판(판 수 +1, 지금 42)과 그 판의 골드가 세이브에 저장됐다**(스테이지 33 그대로, 그 뒤 골드 591,919). 직전 정상본은 `save.dat.bak`이었다.
- `execute_code`(codedom, C# 6): `Object`는 `UnityEngine.Object`로. `SaveIO`(클래스 이름, `Save` 아님)로 세이브를 읽을 수 있다.
- 에디터가 포커스를 잃으면 `StageController.OnApplicationFocus(false)`가 정지 → `Application.runInBackground = true`, `R.paused = false`. 이번엔 `ProjectSettings`의 `runInBackground`가 0으로 남아 있음을 확인했다.

## 확인 못 한 것
- APK·에뮬레이터·실기기 체감. 모든 수치는 PC 에디터 값이다.
- ASTC 압축 결과 화질(특히 UI 글자 그림·아이콘). 실기기 스크린샷으로 봐야 한다.
- 에뮬레이터는 호스트 GPU를 거쳐 ASTC도 소프트웨어로 풀 수 있어 메모리 이득이 실기기보다 작게 보일 수 있다.
- 밤·보름달 판의 모바일 구멍 12개 화면(모바일에서만 적용).

## 남은 일
1. 에뮬레이터 결과에 따라: Graphics APIs를 OpenGLES3 우선으로(에뮬레이터 Vulkan이 느린 경우가 많음, 지금 Vulkan → OpenGLES3).
2. `SpriteDB`가 아틀라스 전체를 한 번에 올리는 구조 → 화면(라운드·세계수·업그레이드)별 묶음 또는 Addressables로 나누기. ASTC로 약 60MB라 급하지 않지만 저사양 기기면 필요. 작업 큼.
3. `MMM_DEV` 출시 빌드에서 빼기 (Player Settings → Scripting Define Symbols, Android·Standalone).
4. 조사 에이전트 목록 중 안 고친 것(효과 중간~작음):
   - `ShroomView.Show` 버섯마다 Transform 8~9번·`sp.bounds` 두 번(값 캐시 가능), HP 알약 `Pill()`의 `r.size`(9-slice 메시 재생성)를 매 프레임.
   - `RoundSim`: `RebuildGrid()`를 SimFrame마다(배속 ×4면 프레임당 4번) → 렌더 프레임당 한 번 검토(시뮬 결과가 바뀌면 안 됨, BalanceSim 지문 대조 필요).
   - `StageHUD` 점수·골드 글자 거의 매 프레임 `U.Fmt` + TMP 다시 만들기 → 10~15Hz.
   - 회오리: LineRenderer 최대 20개 × 40점 매 프레임.
   - `Pool.Trim`/`Get`의 `SetActive` 반복(프레임당 약 6번씩 켜고 끔, `ActivateAwakeRecursively`).
   - 폭풍 날씨 LineRenderer 220개 위치 매 프레임.
   - 레터박스 카메라(`AspectLetterbox`)가 16:9 기기에서도 상주.
5. 회전 칼날 버그: 사용자가 재현 조건(스크린샷·빌드)을 주면 다시.
