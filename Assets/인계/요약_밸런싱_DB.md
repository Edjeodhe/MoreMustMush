## 2. 사용자 결정 (바꾸지 말 것)

- 성장: 초반은 덧셈, 곱셈은 중후반. 같은 능력치의 보너스(노드·코어·별·꼬마·세트)는 **더한다**. 날씨·균사석만 곱한다
- 노드 최대 레벨 3~4. 같은 단계를 더 하고 싶으면 레벨이 아니라 **형제 노드**로
- 업그레이드는 지역·스테이지로 잠그지 않는다. 레퍼런스 **Bills Must Be Paid** — "원만하되 단계적으로 효율 구간이 나뉘게", 100 → 1000처럼 한 번에 뛰지 않게
- 시뮬은 **보수적**: 바 오차 ±60%, 한 판 +30초, 가격은 가장 느린 시드 기준
- 버섯 판매: **의뢰 + 전부 판매 가정, 단 널널하게**(목표 ≈ R88)
- 세금 삭제(2026-10-08). 스테이지마다 보스를 둘 예정 — 지금은 임시 아이콘으로 표시만
- 엑셀 DB: 고칠 때는 **새 버전 파일**로(Ver.03 → 다음은 Ver.04), 저장은 **Excel COM으로만**(openpyxl은 Skima 도형을 지움)
- 일 나누기: 단순 노동은 Sonnet, 추론·이론·관리는 Opus 5.5

## 4. 열린 문제 (우선순위 순)

1. **[열림] T3 가격이 너무 쌈** — 판매·의뢰 수입이 중후반 점수골드의 5.5~12.6배라 실제로는 R56에 끝난다. T5(판매 + 게임 지역 규칙)로 다시 맞춰야 함
2. **[열림] 밤 해금 직후 처치율 0%** — 원칙 P13(해금 판 일반 버섯 ≥50% → 3판 안 80% → 5판 안 90%) 미달. 밤 해금(R20) 전에 공격력 II를 살 수 있게 하는 가격 조건 필요(이론 구조안 S4)
3. **[열림] 지역 경계 수입 점프** — 경계 5판에 ×100~300. S1(램프)은 지역 몫만 줄이고 진입 직후 몰아 사기(×43)는 그대로 → 구조안 S5(진입 직후 살 수 있는 레벨 나누기) 검토
4. **[보류·사용자 결정]** S1 채택 여부 — T6(S1 + 판매) 측정 뒤 질문
5. **[보류·사용자 결정]** 봇 조작에 반응 지연·집중 끊김을 넣을지
6. **[열림] 세금 삭제의 영향 미측정** — 세금은 원래 시뮬에서 빼고 있었으니 가격엔 영향 없음. 단 마을 의뢰가 3판마다 새로 바뀌는 것, 보스 9종이 스테이지로 열리는 것(시뮬에서 이제 열림 → 별 능력치·도감 증가)은 다음 측정부터 반영됨
7. **[열림] 엑셀 DB Ver.03에 `ed_tax`(세금 감면, Upgrade 13004 `tax_mul`)가 아직 있음** — Ver.04 만들 때 같이 지울 것
8. **[열림] 봇이 폐허(R105~)에 못 들어감** — 무한 모드 지역으로 남기기로 해서 의도된 상태
9. **[열림] 균사석 노드 7개** — 균사석 얻을 길이 없어(농장 3단계) 시뮬에서 안 산다
10. **[열림] 실제 플레이 확인 안 됨** — 트리 화면(노드 위치·연결선·잠김 문구 "선행: … 최대 레벨"), 세금 삭제 뒤 화면들
