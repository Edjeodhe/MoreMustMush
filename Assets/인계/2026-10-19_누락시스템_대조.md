# 2026-10-19 UI 개편 전후 시스템 대조 · 알림 띠 · 복귀 보상 창

## 인계 블록

- **[목표]** 리소스 재배치와 UI 개편(씬 4개 분리) 과정에서 빠진 시스템을 찾는다. 옛 구조는 `a01c603`(UI 머지 직전 KHD)이다. 그중 알림과 복귀 보상은 바로 복구한다.
- **[현황]**
  - 대조를 마쳤다. 아래 "빠진 것" 표가 결과다. 밸런스 수치 차이는 계속 조절하는 영역이라 참고로만 적었다(사용자 지시).
  - 복구: 알림 띠(`Toast`, 씬 3개)와 복귀 보상 창(`ReturnPopup`, MainGame·OutGame)을 캔버스에 배치하고 이벤트에 연결했다.
  - 플레이 모드에서 확인한 것: 알림 문구, 창 모양, 닫기 버튼.
  - 확인 못 한 것: 받기 버튼은 테스트 세이브를 바꾸므로 누르지 않았다.
  - 커밋함 (2026-10-19).
- **[반환]** 사용자 확인 후 커밋. 나머지 빠진 것은 우선순위를 정해 하나씩 처리한다.

## 다음 세션 시작점

1. ~~보스 도전 켜기/끄기 버튼~~ · ~~트리 튜토리얼~~ → LKH `8f7ffc8`("튜토리얼, 보스 입장 버튼 복구")에서 복구됐다(사용자 확인). KHD에 합칠 때 `Stage.unity`가 양쪽에서 바뀌므로(LKH +76줄, 이번 Toast 추가) 씬 충돌을 확인한다.
2. ~~일시정지 표시~~ → 사용자가 다른 곳에서 복구했다(10-19 확인 시점에는 원격 브랜치 어디에도 `PauseChanged` 구독이 없어서 아직 푸시 전으로 보인다). 원래 문제는 `StageController.PauseChanged`를 받는 곳이 없어 생기는 문제가 둘이다.

   - 포커스를 잃어도 자동으로 일시정지하지 않는다.
3. 아래 표의 나머지 항목. 다음 후보는 스킨 상점, 세계수 월드를 눌러 탭 열기, 알림 배지, 피버 연출.

## 알려진 것

- 테스트 세이브는 세계수가 아직 해금되지 않은 상태다. 그래서 실제 복귀 흐름에서는 창이 뜨지 않는 것이 정상이다. 모양은 강제로 열어서 확인했다.
- 플레이 테스트 중에 세이브가 저장됐을 수 있다(플레이 시간·`seenT` 정도).

## 추가: 새 기능 해금 안내 (UnlockGuide, 미커밋)

- 도감·세계수·의뢰 버튼이 처음 열리면 튜토리얼처럼 화면을 어둡게 하고 그 버튼만 밝혀 화살표와 "새 기능이 열렸어요: 세계수 / 눌러서 확인해 보세요"를 보여 준다. 그 버튼이나 어두운 곳을 누르면 닫히고, 여러 개가 한꺼번에 열리면 차례로 보인다.
- 코드: `UI/UnlockGuide.cs`, `MainGameController.AnnounceUnlocks` (씬에 `UnlockGuide`가 없으면 예전처럼 알림 문구만). 씬: MainGame `Canvas/UnlockGuide > Window > Dim · Callout(Arrow · Label)`.
- 밝히는 법: 대상 버튼에 정렬 순서를 올린 캔버스를 잠깐 붙인다(닫으면 정렬만 되돌린다). 안내가 떠 있는 동안 `App.ModalPush`로 트리 입력을 멈춘다.
- 한 번만 보인다 (`Unlock.Newly`가 열린 것으로 기록). 기록·스킨·보스 버튼은 이 씬에 아직 없어 대상이 아니다.
- 새 문구 "눌러서 확인해 보세요"는 DB 문자열 시트에 아직 없다(번역 전이라 한국어로 보인다). 번역 추가는 엑셀 COM으로 따로.
- 확인: 플레이 모드에서 세계수 버튼을 강제로 안내해 화살표·문구·밝힘·닫기·입력 복구까지 봤다. 실제 해금 흐름(도감 조건 달성)으로는 돌려 보지 않았다.
