# 2026-10-19 세계수 방치보상 — 해금 후부터 쌓기 · 단계별 강화

## 인계 블록

- **[목표]** 수확 보따리(방치 보상)는 세계수가 해금된 뒤부터만 쌓인다. 세계수 단계가 오를수록 보따리가 강해진다(사용자 지시, 재화 밸런싱 참고).
- **[현황]** 구현했고 컴파일 오류는 없다. csharp 검토의 HIGH 1건을 반영했다. 플레이 모드로 실제 해금 흐름은 돌려 보지 않았다. **미커밋**.
- **[반환]** 사용자 확인 후 커밋한다. 보따리 골드는 사용자 결정으로 판 수입에 연동했다(Z2, 아래 "2차").

## 2차: 보따리 골드를 판 수입에 연동 (Z2, 사용자 결정)

사용자 원칙: 초반에는 직접 플레이가 확실한 이득이어야 한다(지금 초반 보따리가 해금 시점 판 골드의 10배를 넘었다). 갈수록 방치 비중이 커지되, 최대에서도 방치 시간당이 스테이지 시간당과 비슷해지면 안 된다.

- 공식: 보따리 골드/초 = `G.bagGoldPerSec`(일반 판 골드/초 평활값) × `WT.bagRatio[단계]` × 효율항.
  - 효율항: 기존 나무버섯 골드(꼬마 Lv·각성·호감·장식·나이테·gm_herb·treeGold)를 단계 기준 배치 `WT.bagRefGoldH`로 나눈 값 x. 1 아래는 x, 위는 √x, 상한 `bagEffMax` 4. 그래서 세계수 강화가 계속 의미 있다.
  - `bagRatio = {0.004, 0.0054, 0.0106, 0.0134, 0.018, 0.025, 0.037, 0.05}`
- `bagGoldPerSec` (새 세이브 필드): 일반 판(보스·중단·디버그 무한 판 제외)이 끝날 때 `BagBaseUpdate`가 갱신한다. 먼저 `BagSettle()`로 옛 기준을 정산하고, 이전 × 0.7 + 이번(판 골드 ÷ (제한시간 + 30초)) × 0.3로 바꾼다. 운 좋은 한 판에 튀지 않게 하려는 것이다(검증 필수 수정).
- 판 기록이 없으면(옛 세이브 첫 판 전) 골드는 0이고 균사석만 쌓인다.
- `WT.bagMul`은 균사석·개수에만 곱한다.
- 받을 골드·균사석이 둘 다 0이면 보관 시간을 채우지 않는다. 꽉 찬 빈 보따리로 막히던 교착을 고친 것이다(검증 필수 수정).
- 결과(theory·verify 재계산 일치):

  | 세계수 단계 | 8시간 보따리 = 판 몇 개 (기준 배치 / 강화 최대) | 방치 시간당 ÷ 플레이 시간당 |
  |---|---|---|
  | 1 | 2.4 / 4.9 (해금 직후 1.1, 지금까지는 22~46) | 0.4% / 0.8% |
  | 4 | 5.5 / 19.6 | 1.3% / 4.8% |
  | 8 | 19.6 / 78.4 | 5.3% / 20% (구조 상한) |

- 근거 문서: `밸런스설계/이론.md` "보따리 골드 판 수입 연동(Z2)", `밸런스설계/검증.md` 같은 이름 절(조건부 통과 → 필수 2건 반영).
- 에디터 확인: 꼬마 1명 Lv1 세이브로 단계 1→8이 플레이 대비 0.19% → 0.93%로 오르는 것과, 판 기록이 없으면 골드 0인 것을 봤다. 실제 플레이와 봇 시뮬은 하지 않았다.

## 열린 문제

- [권장] 실제 판 사이 시간을 재야 한다. 45초를 넘으면 `bagEffMax`를 3.5로 낮춘다(판 간격이 60초면 8단계 최대가 28%).
- [권장] `gm_herb`·`bagEff`·`treeGold` 설명 문구는 "보따리 ×N"이지만, 골드에는 제곱근·상한으로 들어간다. 문구 정리가 필요하다.
- `bagRefGoldH`는 지금 세계수 수치로 계산한 값이다. 나무버섯·꼬마 수치를 바꾸면 `BalanceData/theory/bag_z2.py`를 다시 돌려야 한다.
- 균사석 노드 `gm_spore`가 보따리 균사석을 크게 늘릴 수 있는데, 아직 측정하지 않았다.
- 봇 시뮬(BalanceSim)에 보따리 수입이 아직 없다. 영향은 판 수입의 0.4~5%로 추정한다.
